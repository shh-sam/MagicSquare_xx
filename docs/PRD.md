# PRD — MagicSquare (4×4 부분 마방진 검증)

**버전:** 0.1 (초안)  
**일자:** 2026-06-04  
**상태:** Draft — Mom Test · 세션 3 워크북 기반  
**상세 보고서:** `Report/01.MagicSquare_ProblemDefinition_Report.md`

---

## 1. 배경

학습자는 4×4 부분 마방진(빈칸 2개, 목표 합 34)을 손으로 맞춘 뒤 10선 합을 검증한다. 합이 맞지 않을 때 어느 줄이 틀렸는지 바로 알 수 없어 한 줄씩 다시 더하는 데 약 10분, 전체 약 20분이 든다 (Mom Test 증거). 본 PRD는 **검증·판정·재현**에 범위를 한정한다.

---

## 2. 목표 · 비목표

### 2.1 목표 (In Scope)

- 4×4 격자의 **10선**(행4 + 열4 + 대각2) 합이 **34**인지 검증
- 불일치 시 **틀린 줄 목록**과 기대/실제 합 제공
- 동일 입력에 대한 결과 **재현** (Test Loop / 자동 테스트)

### 2.2 비목표 (Out of Scope)

| 비목표 | 이유 |
|--------|------|
| 빈칸 **자동 채우기** (Solver) | 표면 문제; Mom Test 진짜 문제와 무관 |
| GridUI / InputHandler / ResultDisplay | Boundary; 세션 3 범위 외 |
| ECB 전체·`MissingFinder` 구현 | 설계 맥락만 유지 |
| 「마방진 프로그램을 만든다」를 제품 목표로 둠 | 표면 문제 |

---

## 3. 사용자

**페르소나:** 4×4 부분 마방진을 손·코드로 다루는 **학습자**.

**주요 시나리오:**

1. 빈칸 위치 표기 → 남은 숫자 파악 → 빈칸 채움  
2. 10선 합 검증  
3. 불일치 시 틀린 줄 특정 (현재: 수동 ~10분 → 제품: 즉시 판정)

---

## 4. 문제 정의

### 4.1 진짜 문제 (한 문장)

부분 마방진(4×4, 빈칸 2개, 합 34)을 손으로 맞춘 뒤 10선 합을 검증할 때 합이 맞지 않으면, 어느 줄이 틀렸는지 바로 판정할 수 없어 한 줄씩 다시 더하는 데 약 10분이 들고, 빈칸 표기부터 완료·재검증까지 약 20분이 걸린다.

### 4.2 표면 문제 (금지 — PRD 목표 아님)

- 4×4 마방진 Solver·Validator·GridUI **프로그램을 만든다**
- ECB 분류·전체 앱을 한 번에 완성한다

## 6. 기능 요구사항

### FR-1: 도메인 Rule

- FR-1.1 격자는 4×4이다.
- FR-1.2 사용 숫자는 1~16이며, 채워진 칸에 중복이 없어야 한다 (빈칸 제외).
- FR-1.3 **10선** 각각의 합은 **34**와 같아야 한다.

### FR-2: Command — 검증

- FR-2.1 `ValidateAllLines(grid)` — 10선 합을 계산하고 34와 비교한다.
- FR-2.2 `ReportMismatchLines(grid)` — 불일치인 행·열·대각을 식별해 반환한다 (전부 통과 시 빈 목록).

### FR-3: (선택) Skill

- FR-3.1 단일 줄(행/열/대각) 합 계산
- FR-3.2 줄 유형·인덱스 라벨 (예: `row_2`, `diag_main`)

### FR-4: Test Loop

- FR-4.1 슬라이드 예시 격자(빈칸 2)에 대한 시나리오 테스트
- FR-4.2 케이스: 전선 통과 / 일부 불일치 / 틀린 줄 ID 고정
- FR-4.3 회귀: 동일 `grid` 입력 → 동일 출력
