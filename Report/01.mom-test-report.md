## 프로젝트 맥락 (4.1 Magic Square)

4×4 격자에 1~16을 한 번씩 배치하고, **모든 행·열·대각선의 합이 같아야** 하는 마방진. 실습 예시에서는 **합 = 34**, 빈칸 2개를 채워 완성한다.

**실습 목표:** ECB 분류 + 문제 인식(실패 조건) 3개 이상 도출.

| ECB | 구성 요소 |
|-----|-----------|
| Entity | `MagicSquare`, `Cell`, `SolveResult` |
| Control | `SquareValidator`, `MissingFinder`, `Solver` |
| Boundary | `GridUI`, `InputHandler`, `ResultDisplay` |

## Mom Test 워크북

### 페르소나

4×4 **부분 마방진**(빈칸 2개)을 **손**으로 맞추거나 **코드**로 다루는 학습자. 수업 실습(4.1 Magic Square) 맥락.

### 인터뷰 답변 (과거 사실)

| # | 질문 요지 | 답변 (과거 사실) |
|---|-----------|------------------|
| 1 | 빈칸 2개 이상일 때 무엇부터 했는지 | **손**으로 시작 |
| 2 | 손으로 첫 동작 | **빈칸 위치 표기** |
| 3 | 그다음 | **남은 숫자 찾기** |
| 4 | 그 시점에서 완료 여부 | **끝까지 맞춤** |
| 5 | 확신 전 마지막 확인 | **가로·세로·대각 합**이 같은지 확인 |
| 6 | 확인 시 재작업 | **다시 함** (한 번에 전부 맞지 않음) |
| 7 | 틀린 이유 | **합이 안 맞음** |
| 8 | 틀린 줄 위치 파악 | **한 줄씩 다시 더해서** 찾음 |
| 9 | 틀린 줄 찾는 데 걸린 시간 | **약 10분** |
| 10 | 빈칸 표기부터 완료까지 총 시간 | **약 20분** |
| 11 | 손으로 끝까지 못 맞추고 그만둔 적 | **없음** |
| 12 | 마지막 코드 시도 시점 | **어제** |
| — | 코드 시 첫 동작 | *(인터뷰 중단 — 미수집)* |

### 표면 문제 (금지 — 솔루션 섞인 문장)

인터뷰 중 **표면 문제 문장은 수집되지 않음**. (솔루션 제안·기능 요구 질문을 하지 않았음.)

향후 ECB·`SquareValidator` 등으로 되돌아가기 쉬운 **금지 예시** (참고용):

- “**검증기**가 있으면 합 확인이 빨라질 것 같다.”
- “**Solver** 알고리즘이 필요하다.”
- “**GridUI**로 빈칸을 표시해 주면 좋겠다.”

### 진짜 문제 (한 문장)

> 부분 마방진을 손으로 맞춘 뒤 가로·세로·대각 합을 검증할 때 합이 맞지 않으면, **어느 줄이 틀렸는지 바로 알 수 없어 한 줄씩 다시 더하는 데 시간이 들고**, 그 과정이 전체 풀이 시간의 상당 부분을 차지한다.

*(솔루션·클래스명 없음. 과거 사실: 재검증 ~10분 / 전체 ~20분.)*

## 인사이트

### 확인된 행동 패턴 (손)

1. 빈칸 위치 표기  
2. 남은 숫자 찾기  
3. 빈칸 채우기 → 완료  
4. 합 검증 → 불일치 시 **선형 탐색식**으로 줄별 재합산  

### 마찰 지점 (ECB·실패 조건 후보)

| 관찰 | STEP 2 연결 힌트 |
|------|------------------|
| 합 불일치를 **사후**에야 발견 | `SquareValidator` — 언제·무엇을 검증할지 |
| 틀린 줄 위치 **비자동** (~10분) | 실패 조건: “어느 줄이 틀렸는지 즉시 특정 불가” |
| 손 풀이는 포기 없음, 코드는 미탐색 | Control/Boundary 설계 시 **손 vs 코드** 경로 분리 |

### 미수집 (후속 인터뷰 권장)

- 어제 코드로 할 때 **맨 처음 한 일**, 막힌 지점, 소요 시간  
- 표면 문제로 들릴 수 있는 본인 발화 2~3문장  
- 합이 틀렸을 때 **어떤 숫자/빈칸을** 바꿨는지
