## 2. 도메인 정의 (Magic Square)

| 규칙 | 설명 |
|------|------|
| 격자 | 4×4 |
| 숫자 | 1~16 각 1회 |
| 목표 합 | **34** (모든 행·열·대각선) |
| **10선** | 가로 4 + 세로 4 + 대각 2 |
| 실습 입력 | **빈칸 2개**인 부분 마방진 → 채워 완성 |

**ECB 참고 (전체 설계 맥락, 이번 세션 구현 범위 아님):**

| 구분 | 구성 요소 |
|------|-----------|
| Entity | `MagicSquare`, `Cell`, `SolveResult` |
| Control | `SquareValidator`, `MissingFinder`, `Solver` |
| Boundary | `GridUI`, `InputHandler`, `ResultDisplay` |

## 3. Mom Test 워크북

### 3.1 페르소나

4×4 **부분 마방진**(빈칸 2개)을 **손**으로 맞추거나 **코드**로 다루는 학습자. 수업 실습(4.1 Magic Square) 맥락.

### 3.2 인터뷰 답변 (과거 사실)

| # | 질문 요지 | 답변 |
|---|-----------|------|
| 1 | 무엇부터 했는지 | **손** |
| 2 | 첫 동작 | **빈칸 위치 표기** |
| 3 | 다음 | **남은 숫자 찾기** |
| 4 | 완료 여부 | **끝까지 맞춤** |
| 5 | 확신 전 확인 | **가로·세로·대각 합** 확인 |
| 6 | 재작업 | **다시 함** |
| 7 | 틀린 이유 | **합이 안 맞음** |
| 8 | 틀린 줄 찾기 | **한 줄씩 다시 더함** |
| 9 | 틀린 줄 찾기 시간 | **약 10분** |
| 10 | 전체 소요 | **약 20분** |
| 11 | 손으로 포기 | **없음** |
| 12 | 코드 시도 | **어제** (이후 중단) |

### 3.3 Mom Test 증거 (인용 3줄)

1. 「가로세로대각합이 같은지 확인」 → 「다시 했어」 → 「합이 안맞음」
2. 「한줄씩 다시 더해서 찾았어」
3. 「10분」 / 「20분」

### 3.4 표면 문제 (잘못된 정의 — 하지 않을 것)

인터뷰 중 **본인 발화로 수집된 표면 문장 없음**. 과제 맥락에서의 **잘못된 정의** 예:

- 「4×4 부분 마방진 **Solver·Validator·GridUI 프로그램**을 만든다.」
- 「**ECB로 분류한** MagicSquare 앱을 만든다.」
- 「**검증기/Solver/UI**가 있으면 좋겠다.」(미래 가정·솔루션 혼입)

### 3.5 진짜 문제 (한 문장)

> 부분 마방진(4×4, 빈칸 2개, 목표 합 34)을 손으로 맞춘 뒤 **10선** 합을 검증할 때 합이 맞지 않으면, 어느 줄이 틀렸는지 바로 **판정**할 수 없어 한 줄씩 다시 더하는 데 약 **10분**이 들고, 빈칸 표기부터 완료·재검증까지 약 **20분**이 걸린다.

*(솔루션·도구명 없음.)*

## 4. 문제 정의 (세션 3)

### 4.1 주제 한 문장

4×4 부분 마방진(합 34, 10선, 빈칸 2개)을 채운 뒤, **10선 합이 34인지 검증**하고, 불일치 시 **어느 줄이 틀렸는지 바로 판정**할 수 있는지 확인한다.

### 4.2 R-G-I-O

| 항목 | 내용 |
|------|------|
| **Role** | 부분 마방진을 손·코드로 맞추는 **학습자** |
| **Goal** | 수동 「한 줄씩 다시 더하기」(~10분) 없이 **불일치·틀린 줄**을 재현 가능하게 판정 |
| **Input** | 4×4 격자 (1~16 일부 채움), 목표 합 **34** |
| **Output** | 전 줄 일치 여부; 불일치 시 **틀린 행·열·대각** + 기대 34 vs 실제 합; **재현 가능한 판정 결과** |

### 4.3 성공 기준 (Mom Test 연결)

| # | 기준 | 증거 |
|---|------|------|
| 1 | **10선** 합 검증을 한 절차로 수행·기록 | 「가로세로대각합이 같은지 확인」 |
| 2 | 불일치 시 **어느 줄**인지 출력 (true/false만 금지) | 「합이 안맞음」·「한줄씩 다시 더해서 찾았어」 |
| 3 | 동일 격자·동일 입력 → 검증 결과 **재현** (Test Loop) | 「10분」/「20분」 수동 비용 → 판정 단계 회귀 테스트 |

### 4.4 표면 문제 — 프로젝트에서 하지 않을 것

- Solver·GridUI·ECB **전체**를 이번 목표로 삼기
- 빈칸 자동 채우기·UI를 우선 구현
- 합만 true/false, **틀린 줄 특정** 미루기
- Mom Test 없이 「Validator 있으면 좋겠다」로 범위 결정

### 4.5 8계층 — 이번 세션 범위

| 계층 | 범위 |
|------|------|
| **Rule** | 1~16 각 1회, 4×4, 10선 합 = 34, 빈칸/중복 검증 규칙 |
| **Command** | `ValidateAllLines`, `ReportMismatchLines` (채우기 제외) |
| **(Skill)** | *(선택)* 줄 합 계산, 34 비교, 행·열·대각 라벨 |
| **Test Loop** | 맞음/틀림/틀린 줄 시나리오 pytest |

**이번 세션 제외:** Entity 완성, Boundary, `Solver`, `MissingFinder`.

## 6. 실패 조건 후보 (STEP 2 연결)

1. 합 불일치를 채운 **후**에야 발견 (사전 검증 없음)
2. 불일치 시 **어느 10선**인지 즉시 특정 불가 (~10분 수동 탐색)
3. 동일 격자에 대해 검증 결과가 실행마다 달라짐 (재현 불가)
