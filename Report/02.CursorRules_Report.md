## 2. 배경

문제 정의(01)와 PRD v0.1은 **무엇을 검증할지**(10선·34·틀린 줄 판정)에 집중했다.  
코드 TDD·ECB 실습을 시작하기 전, Cursor AI가 매 세션마다 동일한 제약(빈칸 0×2, entity import 금지, Domain Mock 금지 등)을 따르도록 **`.cursorrules`** 초안이 필요했다.

## 4. 도메인 규칙 (Rules 파일 반영)

| 규칙 | `.cursorrules` 표현 |
|------|---------------------|
| 격자 | 4×4 |
| 빈칸 | **0** 정확히 **2개** |
| 숫자 | 1~16 각 1회 |
| 마방진 상수 | **34** (10선) |
| Solver 출력 | `int[6]` = `[r1,c1,n1,r2,c2,n2]`, 좌표 **1-index** |
| 오류 | E001~E007 — **Boundary**; Entity는 **E001~E005 처리 금지** |

> PRD v0.1은 검증(Validator) 중심이나, Rules는 수업 슬라이드·Solver 출력 형식까지 포함해 **전체 ECB 맥락**을 고정한다.

## 5. 아키텍처 · 테스트 정책

### 5.1 ECB

```
Boundary → Control → Entity
```

- **boundary:** 입출력, E001~E007, UI/CLI  
- **control:** 유스케이스 조율, Boundary↔Entity 변환  
- **entity:** 순수 도메인; 프로젝트 내부 `*` import **금지**

패키지 예: `src/magicsquare/boundary/`, `control/`, `entity/`

### 5.2 Dual-Track

| Track | Layer | Mock |
|-------|-------|------|
| Logic | entity, control | **금지** |
| UI | boundary | **허용** |

### 5.3 테스트 ID · 파일명

| Track | ID | 파일 |
|-------|-----|------|
| Logic | `D-*` | `tests/test_d_*.py` |
| UI | `U-*` | `tests/test_u_*.py` |

## 7. AI 행동 규칙

- 응답 **한국어**
- TDD 시 매 턴 **Phase** / **Layer** / **Track** 선언
- **최소 diff** — 요청 범위 외 파일·기능 추가 금지
- **git commit·push** — 사용자 명시 요청 시만
- 표면 문제 금지 — 「Solver·GridUI 프로그램 만든다」를 목표로 삼지 않음
